# Distilling MT models → slimt catalog packs

**Read order: RUNBOOK first (how to train a new pair), then the pillars for why/gotchas, then the run-log for history.**

# ▲ APEX — goal & hard constraint
Add en↔X pairs to the app's offline **slimt/bergamot catalog** by DISTILLING teacher models (OPUS-MT or NLLB-200) into tiny **base-memory SSRU students**, trained with **OpusTrainer** augmentation on rented **vast.ai** GPUs, int8-quantized, packaged into the BunnyCDN bucket. slimt's decoder is **SSRU-only** → it cannot run OPUS-MT/CTranslate2 teachers directly → distillation is the ONLY path (Argos = CT2, dead end). Scripts: this dir (`scripts/opus-trainer/`). Compute: **bigserver** (CPU, free) + **vast.ai** (GPU, ~$8/pair).

# ▶ RUNBOOK — add a new pair, worked example en↔sw (do these in order)
Prereqs: bigserver up (docker images `marian-train:cpu`+`marian-bmt:cpu`, `/fast_storage/david/opus-trainer/venv`, `/nvme2/prom/marian-work` with built fast_align+extract-lex, `/nvme2/prom/bins/marian.cuda`); vast CLI+credits (`~/.ssh/davidkey`); a joint SPM vocab (`.spm`-named). Each command's WHY/gotchas → the matching pillar in Layer 3.

**0. Gate the teacher** (bigserver, free) — `nllb_gate.py --pairs eng_Latn-swh_Latn,swh_Latn-eng_Latn --limit 80` (or `validate_teacher.py` for OPUS-MT). Pick a teacher per direction (chrF++ ≥~50; NLLB for into-English / low-resource / where OPUS-MT is absent). → Pillar 2.

**1. Prep data + BUILD the joint vocab** (bigserver, ~30-40min) — KD pool, run WITHOUT --skip-spm the FIRST time so prep trains the vocab: `prep_data.py --lang sw --workdir /nvme2/prom/ensw --jobs 16` → cleaned bitext + `ensw/spm/vocab.ensw.model` (32k joint unigram on both sides, 10M sample); **`cp ensw/spm/vocab.ensw.model vocab.ensw.spm`** (marian needs the `.spm` extension). NOTE: `--skip-spm` is only for REUSE of an EXISTING vocab — the tl runbook shows it because tl v2 reused take-1's /nvme2/prom/opus-trainer/spm/vocab.entl.model; a NEW language has no vocab yet (joint SPM is language-specific, can't reuse entl) so you must build one here. Finetune set (reuse the vocab just built): `prep_data.py --lang sw --only TED2020,Tatoeba,QED,bible-uedin,tico-19,wikimedia --workdir /nvme2/prom/ensw-ft --skip-spm`. KD source PER DIRECTION: sw→en → `zcat ensw/clean/train.ensw.sw.gz | LC_ALL=C sort -u | shuf | head -10000000 | gzip > kd.sw.gz`; en→sw → same on `train.ensw.en.gz` → kd.en.src.gz. PER DIRECTION build: a held-out **valid** (2-col `src\ttrg` in the direction's order — sw→en: `sw\ten`, en→sw: `en\tsw`) for train/finetune early-stopping, AND a **devtest** (1-col SOURCE-side sentences — sw for sw→en, en for en→sw) for the quantize dump-quantmult step. → Pillar 3.

**2. KD** (vast, shard K boxes — decide K upfront, 4-6) — `split -n l/K kd.sw.gz`; each box: run `vast_setup.sh` env, relay `distill_data.py`+shard, then `distill_data.py --model facebook/nllb-200-distilled-600M --src-lang swh_Latn --tgt-lang eng_Latn --src shardN.sw.gz --out shardN.en.gz --max-batch-tokens 3072 --beam 4`. `cat` shard outputs IN ORDER → kd.en.gz; save to bigserver; **destroy boxes**. → Pillars 2,6.

**3. Align** (bigserver, in container) — `docker run … marian-train:cpu bash /scripts/align.sh kd.sw kd.en <out> /nvme2/prom/marian-work` → `train.tsv` (3-col). Same on the curated finetune set → `ft/train.tsv`. → Pillar 4.

**4. Train + finetune** (vast, CUDA-11.8 box) — image `nvidia/cuda:11.8.0-cudnn8-runtime-ubuntu22.04`, `apt install libopenblas0 python3-pip`, `pip install opustrainer`; relay marian.cuda+configs+vocab.spm+train.tsv+valid.tsv+ft/train.tsv. `MARIAN=/root/marian.cuda train_student.sh train.tsv vocab.spm valid.tsv model/model.npz 0`, then (auto-chain) `finetune_student.sh ft/train.tsv vocab.spm <KD .best.npz> valid.tsv model_ft/model.npz 0`. Multi-GPU → run the EFFICIENCY GATE first. Stop at plateau; pull `model_ft/*.best-ce-mean-words.npz`. → Pillar 4.

**5. Quantize + shortlist** (bigserver, marian-bmt container; step-2 on host venv) — `quantize_export.sh model_ft.best.npz vocab.spm devtest.sw quant/` → `model.intgemm.alphas.bin` (~31.5MB). `shortlist.sh kd.sw kd.en vocab.spm shortlist/ /nvme2/prom/marian-work` → `lex.50.50.s2t.bin`. → Pillar 5.

**6. Benchmark** (laptop) — `benchmark_slimt.py --lang sw --src sw --model … --shortlist none` (model), then with the shortlist (pack). Compare to teacher gate + any old pack. → Pillar 5.

**7. Deploy** (laptop) — gzip pack into `bucket/…/models/en-sw|sw-en/<dated_dir>/exported/`; edit `gcs_models.json` (paths + model.uncompressedHash sha256-of-uncompressed + size + metrics); `regen_index.sh`; `cp app/src/main/assets/index_v5.json ../bucket/`; `sync.sh` — then **force-PUT index_v5 + purge** (bunny_sync size-only skip). Verify live. → Pillar 5.

# ▶ IMPROVE — lift an EXISTING pair's FLORES (option-1 finetune TESTED & DISPROVEN on tl 2026-07-13)
CONTEXT (diagnosed on tl→en, see Pillar 2): the student lands ~5-6 chrF below the teacher on FLORES. The hypothesis was a KD-SOURCE-DOMAIN gap (student learns the teacher on crawl-domain source) fixable by clean eval-adjacent teacher labels.
1. **Domain-adaptive KD-finetune — TESTED, DOES NOT WORK.** Teacher-translated 163k clean Leipzig-wiki Tagalog and finetuned the KD ckpt on it → FLORES **59.88**, WORSE than the shipped human-curated finetune (60.57), with KD-agreement UP (72.83). Lesson: more teacher-labeled data (even clean/wiki) reinforces teacher-STYLE and does NOT close the human-ref gap; the FLORES-lifting signal is HUMAN references. Do not repeat this approach. Full analysis → Pillar 2 "FOLLOW-UP EXPERIMENT".
2. **Re-KD from scratch** — fold clean monolingual into the KD source POOL and retrain. UNTESTED and now expected MODEST (a pure clean-teacher finetune reinforced style rather than helping), so NOT worth ~$8 on spec.
**What actually gates a low-resource pair's FLORES** (revised): HUMAN parallel finetune SUPPLY (the real constraint — scarce for low-resource), TEACHER quality, and STUDENT CAPACITY (the ~6 student-vs-teacher gap looks like KD compression → a bigger student is the most promising untried lever). Leipzig Tagalog inventory for reference: only `tgl_wikipedia_{2016,2021}_100K` (~163k unique after dedup).
3. **Bicleaner-salvage finetune — PROVEN (sw→en +1.6 chrF++), but DIRECTION-DEPENDENT.** Expand the tiny curated finetune set by salvaging genuinely-aligned HUMAN pairs from the noisy mined pool (the ones we excluded from finetune for semantic-misalignment risk). Recipe (Swahili 2026-07-14, ~$3 all-in):
   - Install: `pip install bicleaner-ai "tensorflow[and-cuda]==2.20.0"` (bicleaner-ai is TENSORFLOW; needs a GPU box — CPU is ~130h for 6M pairs, GPU 4090 ~730 pairs/s ~2.25h). Model = **`bitextor/bicleaner-ai-full-en-xx`** (ONE multilingual XLM-R-large; works for any XLM-R language incl. sw — no per-pair model exists/needed).
   - Score the cleaned mined pool (2-col `src\ttgt`): `bicleaner-ai-classify --scol 1 --tcol 2 -s <xx> -t en --score_only --disable_hardrules --mixed_precision pool.tsv pool.scored bitextor/bicleaner-ai-full-en-xx`. `--disable_hardrules` because our pool is already heuristically cleaned; without it, needs the `bicleaner-ai[hardrules]` extra. (sw pool: mean 0.285, 64% junk <0.3.)
   - Keep **≥0.8** (sw: 908k of 6M), `align.sh` them, cat with the curated set, `finetune_student.sh` the KD ckpt on the merged set.
   - **ONLY boost the WEAK/large-gap direction, and judge by chrF NOT ce**: crawl-domain TARGET data lowers token-ce while it can HURT clean-domain chrF — sw→en (gap −7.7, clean English target) +1.6; en→sw (gap −1.6, crawl-Swahili target) −0.4 despite ce dropping 1.93→1.69. See RUN LOG "Swahili bicleaner boost".
FOR NEW LANGS (Swahili 2026-07-13): no cheap KD-source-domain fix exists — leave the KD pipeline as-is. FLORES levers in priority order (there is NO arch cap — see Pillar 2 gate-rule; base-memory→70 / tiny→75 chrF++ in our own catalog, all pair-bound): (1) **MORE HUMAN finetune data** = the real constraint — a low-resource pair's curated set is tiny (sw curated = only 9k pairs), so EXPAND it by running **bicleaner-ai over the mined corpora** (CCMatrix/CCAligned) to salvage genuinely-aligned human pairs → these are **finetune material** (both sides human; KD doesn't need them, the teacher regenerates targets), the cheapest real lever and the one that lifts FLORES *above* the teacher; (2) a **bigger student** (the ~6 student-vs-teacher gap is likely KD compression); (3) a **better teacher** (NLLB-1.3B/3.3B). Bicleaner deferred until after sw↔en ships.

## 1. PIPELINE  (phase → script → where → ~time)
- **P0 gate** — validate_teacher.py (OPUS-MT) / nllb_gate.py (NLLB) → FLORES-200 devtest chrF++/spBLEU. bigserver CPU, cheap. Decide teacher before spending GPU.
- **P1 prep** — prep_data.py → cleaned en↔X bitext + joint 32k SPM. bigserver CPU, ~20-30min (parallelized).
- **P2 KD** — distill_data.py (CT2 int8 teacher forward-translate) → synthetic targets. vast GPU, ~5-6h/5M; SHARD across N boxes.
- **align** — align.sh (fast_align) inside marian container → 3-col guided-align TSV. bigserver, ~20min/10M.
- **P3 train** — train_student.sh (marian.cuda + OpusTrainer) → base-memory student. vast GPU, converges in a few h.
- **P3b finetune** — finetune_student.sh (quantize-aware, on curated clean set). vast GPU, ~1h.
- **P4 quant** — quantize_export.sh (browsermt 3-step int8) + shortlist.sh (SPM-subword). bigserver container, <20min.
- **bench** — benchmark_slimt.py (slimt on FLORES). laptop, <5min.

## 2. TEACHERS
- Student arch = **base-memory** (dim-emb 384, dec-cell ssru dec-depth 4, enc gru bidir depth 6, ffn 1536, tied-embeddings-all). `tiny` = 256/dec-2 (id-en, ru-en).
- **base-memory vs tiny — UNRESOLVED (no rule that avoids two training rounds)**: shipped major packs use base-memory (bigger, better when the data supports it); a few pairs use tiny. We do NOT have a validated upfront criterion, and neither is mozilla's exact rule documented here (they ship both configs, likely chosen empirically per language). The one real signal we saw: base-memory's *finetune* overfits fast on a small curated set (tl→en, 116k → valid ce rose after ~4k updates) — but early-stopping catches it, so it's wasted compute, not a broken model; the KD phase (10M teacher data) is NOT capacity-starved for base-memory. Working heuristic (UNVALIDATED): default base-memory when KD ≥ ~few M and finetune ≥ ~50-100k; consider tiny only if genuinely data-starved or if pack-size/latency dominates. TODO: find a cheap a-priori proxy (P0 teacher gate score × corpus size?) so the choice doesn't need two full trains to compare.
- **OPUS-MT** (HF Helsinki-NLP): per-pair ~75M. Good for well-resourced pairs. Gaps: sw→en has no dedicated model (`mul-en` hallucinates, chrF 24); en/ur→ur both hallucinate (chrF 25-31). Convert to CT2 in distill_data.py automatically.
- **NLLB-200-distilled** (600M / 1.3B): ONE multilingual model, lang-code tokens (eng_Latn, tgl_Latn, swh_Latn, urd_Arab…). Cross-lingual transfer helps low-resource + into-English; cleaner targets. Needs tokenizer.src_lang + CT2 target_prefix.
- **Gate rule**: FLORES chrF++ ≥ ~50 (per direction). Student SHOULD land within ~1-2 of teacher. **NO confirmed capacity cap** — the old "base-memory caps ~60" is WITHDRAWN as a one-pair over-generalization: the shipped base-memory catalog (~137 pack entries) spans chrF ~28 (en→ja) to ~77 (en→no), 70/137 above 60. Absolute chrF is NOT comparable across target languages — target morphology/tokenization/script set the attainable level independent of the student (chrF is char-n-gram F: agglutinative/free-order targets admit many surface forms → lower chrF for equal quality; space-free/logographic zh/ja/th score 28-42 as a metric artifact), and high scorers (fr/es/pt/de/id ~65-77) are just the highest-RESOURCE pairs (teacher is excellent, student inherits it), NOT "close to English". So a per-pair "~60" describes that pair, not the arch. REAL open puzzle: tl→en missed its teacher by ~5.7 (NLLB 66.4 → shipped student 60.7), far past the ~1-2 rule — a distillation-pipeline gap, DIAGNOSABLE not a ceiling. Suspects: (a) KD-domain mismatch — student learns from teacher outputs over the noisy KD *source* corpus but is scored on clean FLORES; (b) teacher-label quality — NLLB fed noisy KD source emits worse targets than its FLORES score implies; (c) thin/overfit finetune (base-memory overfits ~116k curated). **DIAGNOSED 2026-07-13** (diag_finetune_tlen.sh, marian-decoder both ckpts × FLORES/KD-domain): FLORES pre-ft 57.70 → post-ft 60.57 (teacher 66.4); KD-domain student-vs-teacher pre-ft 72.46 → post-ft 70.66. Reading: (c) overfit RULED OUT — finetune raises FLORES +2.9 while lowering KD-agreement −1.8 = correctly re-domaining toward clean human refs, working as intended. Capacity/underfit RULED OUT — student reproduces the teacher at 72.5 on-domain, plenty of headroom (caveat: slice was in-train, so upper bound). So the −5.7 is (a)+(b) the **KD-domain/label gap**: student faithfully learned the teacher *as it behaves on the noisy KD-source domain* (Tagalog crawl/mined mono), which cashes out to ~60.6 on FLORES even though the same teacher scores 66.4 on clean FLORES input the student never trained toward. **FOLLOW-UP EXPERIMENT 2026-07-13 (validate the "clean-domain finetune" fix) — DISPROVEN**: teacher-translated 163k clean Leipzig-wiki Tagalog (eval-adjacent) and finetuned the SAME KD ckpt on it (vast 4090, tlstage/bootstrap.sh). Result FLORES **59.88** (WORSE than the human-curated 60.57) with KD-agreement **72.83** (HIGHER than KD-only 72.46). This FLIPS the reading above: the FLORES-lifting signal is HUMAN references, not clean-domain teacher labels — the human ft pulls the student AWAY from teacher-style toward human refs (agreement 72.5→70.7, FLORES +2.9), while MORE teacher output (even clean/wiki) reinforces teacher-style (agreement 72.5→72.8) and does NOT close the human-ref gap. You cannot out-human-match the teacher by feeding it more of the teacher. So the ACTUAL levers for a low-resource pair's FLORES are: (1) HUMAN parallel finetune SUPPLY — the real constraint (60.6 ≈ what tl's available human set buys; scarce by definition for low-resource); (2) a BETTER TEACHER (closer-to-human outputs); (3) STUDENT CAPACITY — the ~6 student-vs-teacher gap is likely KD compression, which a bigger student would shrink (earlier "capacity ruled out" was too strong: high on-domain teacher-AGREEMENT ≠ matching the teacher's human-ref SCORE). Re-KD (clean domain in the 10M base) stays untested but is expected modest, since even a pure clean-teacher FINETUNE reinforced style rather than helping — NOT worth ~$8 on spec.
- Gate scores (FLORES devtest, beam 4): tl→en OPUS 58.5 / NLLB-600M 66.4 / 1.3B 68.6; en→tl OPUS 59.4 / 600M 58.4 / 1.3B 60.3; en→sw 61.3, sw→en 64.4, en→ur 48.4, en/hau→ 49.5/55.5, en/uig→ 39.7/47.4 (600M) 42.8/49.6 (1.3B), pan_Guru→en 63.6.

## 3. DATA
- Corpora resolved via OPUS `opus_get`. ALLOWLIST curated (skip Ubuntu/GNOME/translatewiki/ELRC localization junk, XLEnt entity pairs).
- **CLEANING** = mozilla OpusCleaner filters ported into prep_data.py: deescape (Moses special-chars), fix_wiki (footnotes/wikilinks/headings/.mw-parser-output), alpha_ratio (letter-category word0.6/alpha0.4), num_mismatch, url_mismatch, max_word_len 150, + strip_artifacts (♪/[Applause]/`<i>`), + fastText langid both sides. bicleaner-ai (ML misalignment filter) = deferred, gate on need. mozilla's remove_frequent_patterns has NO ♪ — our strip_artifacts is more targeted.
- **KD vs FINETUNE corpus SPLIT (key insight)**: KD trains on (source, TEACHER-output) → a source corpus's MISALIGNMENT is irrelevant (teacher regenerates the target); only source-side monolingual quality matters → **KD source = full allowlist** (keep noisy CCAligned, 91% dropped by filters but harmless). Finetune uses ORIGINAL bitext BOTH sides → misalignment teaches wrong mappings → **finetune = curated/human only** (TED2020,Tatoeba,QED,bible-uedin,tico-19,wikimedia), exclude CCAligned + all mined. Generate finetune as a SEPARATE `--only` prep (dedup pool has no provenance). Hold out ~2000 for the valid set (leakage-free). **WHY human-only (not just "cleaner")**: mined corpora carry SEMANTIC misalignment — pairs that look parallel but aren't translations (rife in CCAligned/CCMatrix crawl, "the misaligned community cases"). Our heuristic filters catch SURFACE junk (wrong-lang, length, symbols) but CANNOT detect semantic misalignment — only **bicleaner-ai** (ML, deferred) can. On the both-sides finetune bitext that garbage directly teaches wrong source→target mappings, and finetune is what sets the final clean-domain quality — so we sidestep the whole class with human corpora instead of adding the bicleaner dependency. KD is immune (teacher regenerates the target), so KD keeps the full noisy allowlist.
- **prep_data.py PARALLELIZED**: multiprocessing.Pool, worker cleans **20k-line blobs** (not per-line), bounded in-flight (jobs×4), --jobs / --skip-spm, py3.9 needs `from __future__ import annotations`. NLLB corpus (~3.2GB) dominates ~6× all others → shard by LINE not corpus.
- KD source = dedup tl (LC_ALL=C sort -u) → shuf (fixed seed) → 10M subsample.

## 4. TRAINING
- **marian builds**: TRAIN = upstream marian-nmt/marian-dev @ e8a1a25 (mozilla's pin; SSRU+guided-align+int8 built in; CUDA 11.8 = first with Ada/sm_89 for 4090). CONVERT = **browsermt/marian-dev** (upstream marian-conv emits intgemm type 65537 slimt REJECTS; browsermt = legacy 0x4101 + int8 embeddings → ~30MB). npz is portable across forks; only conversion needs browsermt. Saved GPU binary: `/nvme2/prom/bins/marian.cuda` (755MB, built on nvidia/cuda:11.8.0-devel-ubuntu22.04). WHY e8a1a25 specifically: it's the commit **mozilla/translations pins** in their pipeline (matches their SSRU base-memory configs + guided-align + int8 behavior). **Why we can't just bump marian to a CUDA-12.8/Blackwell version**: it's a chain of pins — train-marian `.npz` → **browsermt marian-conv** (stale fork, emits slimt's legacy int8 intgemm) → **slimt loads that exact format**. slimt is the anchor. A newer training marian must still support SSRU+guided-align AND produce an npz the old browsermt converter can read; bumping = re-validating the whole train→convert→slimt-load chain (~a day), not a config flip. Only worth it if 4090s dry up / Blackwell gets much cheaper.
- **OpusTrainer**: `opustrainer-train --config <cfg> <marian> …` pipes augmented 3-col TSV → marian **STDIN** (marian gets `--tsv` + NO `--train-sets`, + required `--shuffle batches --no-restore-corpus` for the non-seekable stream). Modifiers for Latin bicameral+phonemic src (configs/opustrainer.student.yml, flattened from mozilla): UpperCase 0.07 / TitleCase 0.05 / RemoveEndPunct 0.2 / Typos 0.05 / Noise 0.0005 (Tags OMITTED — needs PyICU + SPM-align remap). Perturbs a FRACTION of existing lines in-place → ~0 wall-cost, NOT more data. Big robustness win (also gives multi-sentence robustness — RemoveEndPunct/Noise stop the early-EOS drop). Wired into BOTH train_student.sh + finetune_student.sh.
- **guided-alignment REQUIRED** (config `guided-alignment: 2`, whitespace-level; prod uses the model's alignment output for bold/format transfer). fast_align/atools run INSIDE the marian container (bigserver host glibc 2.31 too old for the binaries).
- **MULTI-GPU** = data-parallel on ONE box (`marian --devices 0 1 …` + --sync-sgd), NOT multi-machine (needs MPI + interconnect). **MANDATORY EFFICIENCY GATE**: before committing, ~500-1000-update smoke, per-GPU util must be >80% each (reject 25%-idle) + ~1.7-1.9× throughput vs 1-GPU. Risk: the single OpusTrainer stdin pipe can starve 2+ GPUs → bump opustrainer --batch-size/--chunk-size + marian --maxi-batch/--workspace, or materialize the augmented TSV once and feed marian's reader directly.
- **GOTCHAS**: (a) vocab MUST be named `.spm` — marian detects SPM by extension; `.model` → "DefaultVocabulary must not contain empty lines". (b) **pkill self-match**: `pkill -f <pattern>` kills ANY process whose cmdline contains `<pattern>` literally — including the pkill command itself AND your outer ssh shell if the same command also `echo`s/`pgrep`s that pattern (this bit me: cost my session). Fix: **bracket the first char** so your own commands hold `[m]arian.cuda` (which the regex `[m]arian.cuda` does NOT match) while the real target's cmdline holds the literal `marian.cuda` (which it DOES) — `pkill -f '[m]arian.cuda'`, and bracket the pattern EVERYWHERE it appears in that command line, not just the pkill. Belt-and-suspenders: run pkill from a separate script file (its cmdline is just `bash kill.sh`, no pattern). (c) early-stopping 20 can run for hours on an epsilon-best plateau (model keeps setting tiny new bests, resetting the counter) → stop manually once converged; --keep-best preserves the best regardless. ## 5. QUANTIZE → PACKAGE → DEPLOY
