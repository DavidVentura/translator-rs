# ▲ APEX — goal & hard constraint
Add en↔X pairs to the app's offline **slimt/bergamot catalog** by DISTILLING teacher models (OPUS-MT or NLLB-200) into tiny **base-memory SSRU students**, trained with **OpusTrainer** augmentation on rented **vast.ai** GPUs, int8-quantized, packaged into the BunnyCDN bucket. slimt's decoder is **SSRU-only** → it cannot run OPUS-MT/CTranslate2 teachers directly → distillation is the ONLY path (Argos = CT2, dead end). Scripts: this dir (`scripts/opus-trainer/`). Compute: **bigserver** (CPU, free) + **vast.ai** (GPU, ~$8/pair).

# ▶ RUNBOOK — add a new pair, worked example en↔sw (do these in order)
Prereqs: bigserver up (docker images `marian-train:cpu`+`marian-bmt:cpu`, `/fast_storage/david/opus-trainer/venv`, `/nvme2/prom/marian-work` with built fast_align+extract-lex, `/nvme2/prom/bins/marian.cuda`); vast CLI+credits (`~/.ssh/davidkey`); a joint SPM vocab (`.spm`-named). Each command's WHY/gotchas → the matching pillar in Layer 3.

**0. Gate the teacher** (bigserver, free) — `nllb_gate.py --pairs eng_Latn-swh_Latn,swh_Latn-eng_Latn --limit 80` (or `validate_teacher.py` for OPUS-MT). Pick a teacher per direction (chrF++ ≥~50; NLLB for into-English / low-resource / where OPUS-MT is absent). → Pillar 2.

**1. Prep data + BUILD the joint vocab** (bigserver, ~30-40min) — KD pool, run WITHOUT --skip-spm the FIRST time so prep trains the vocab: `prep_data.py --lang sw --workdir /nvme2/prom/ensw --jobs 16` → cleaned bitext + `ensw/spm/vocab.ensw.model` (32k joint unigram on both sides, 10M sample); **`cp ensw/spm/vocab.ensw.model vocab.ensw.spm`** (marian needs the `.spm` extension). NOTE: `--skip-spm` is only for REUSE of an EXISTING vocab — the tl runbook shows it because tl v2 reused take-1's /nvme2/prom/opus-trainer/spm/vocab.entl.model; a NEW language has no vocab yet (joint SPM is language-specific, can't reuse entl) so you must build one here. Finetune set (reuse the vocab just built): `prep_data.py --lang sw --only TED2020,Tatoeba,QED,bible-uedin,tico-19,wikimedia --workdir /nvme2/prom/ensw-ft --skip-spm`. KD source PER DIRECTION: sw→en → `zcat ensw/clean/train.ensw.sw.gz | LC_ALL=C sort -u | shuf | head -10000000 | gzip > kd.sw.gz`; en→sw → same on `train.ensw.en.gz` → kd.en.src.gz. PER DIRECTION build: a held-out **valid** (2-col `src\ttrg` in the direction's order — sw→en: `sw\ten`, en→sw: `en\tsw`) for train/finetune early-stopping, AND a **devtest** (1-col SOURCE-side sentences — sw for sw→en, en for en→sw) for the quantize dump-quantmult step. → Pillar 3.

**2. KD** (vast, shard K boxes — decide K upfront, 4-6) — `split -n l/K kd.sw.gz`; each box: run `vast_setup.sh` env, relay `distill_data.py`+shard, then `distill_data.py --model facebook/nllb-200-distilled-600M --src-lang swh_Latn --tgt-lang eng_Latn --src shardN.sw.gz --out shardN.en.gz --max-batch-tokens 3072 --beam 4`. `cat` shard outputs IN ORDER → kd.en.gz; save to bigserver; **destroy boxes**. → Pillars 2,6.

**3. Align** (bigserver, in container) — `docker run … marian-train:cpu bash /scripts/align.sh kd.sw kd.en <out> /nvme2/prom/marian-work` → `train.tsv` (3-col). Same on the curated finetune set → `ft/train.tsv`. → Pillar 4.

**4. Train + finetune** (vast, CUDA-11.8 box) — image `nvidia/cuda:11.8.0-cudnn8-runtime-ubuntu22.04`, `apt install libopenblas0 python3-pip`, `pip install opustrainer`; relay marian.cuda+configs+vocab.spm+train.tsv+valid.tsv+ft/train.tsv. `MARIAN=/root/marian.cuda train_student.sh train.tsv vocab.spm valid.tsv model/model.npz 0`, then (auto-chain) `finetune_student.sh ft/train.tsv vocab.spm <KD .best.npz> valid.tsv model_ft/model.npz 0`. Multi-GPU → run the EFFICIENCY GATE first. Stop at plateau; pull `model_ft/*.best-ce-mean-words.npz`. → Pillar 4.

**5. Quantize + shortlist** (bigserver, marian-bmt container; step-2 on host venv) — `quantize_export.sh model_ft.best.npz vocab.spm devtest.sw quant/` → `model.intgemm.alphas.bin` (~31.5MB). `shortlist.sh kd.sw kd.en vocab.spm shortlist/ /nvme2/prom/marian-work` → `lex.50.50.s2t.bin`. → Pillar 5.

**6. Benchmark** (laptop) — `benchmark_slimt.py --lang sw --src sw --model … --shortlist none` (model), then with the shortlist (pack). Compare to teacher gate + any old pack. → Pillar 5.

**7. Deploy** (laptop) — gzip pack into `bucket/…/models/en-sw|sw-en/<dated_dir>/exported/`; edit `gcs_models.json` (paths + model.uncompressedHash sha256-of-uncompressed + size + metrics); `regen_index.sh`; `cp app/src/main/assets/index_v5.json ../bucket/`; `sync.sh` — then **force-PUT index_v5 + purge** (bunny_sync size-only skip). Verify live. → Pillar 5.

# ▶ IMPROVE — lift an EXISTING pair's FLORES (option-1 finetune TESTED & DISPROVEN on tl 2026-07-13)

**SCOPE OF THAT DISPROOF (narrowed 2026-08-31).** What failed on tl was a
DOMAIN-ADAPTIVE KD finetune: the same teacher re-translating clean wiki text, which
reinforces teacher style and cannot exceed the teacher. A finetune on CURATED
FRONTIER-GENERATED data is a different thing and it works — on en→ka it moved
camera-path sign strings +12.47 chrF++ over the KD student and 8.67 ABOVE the
teacher. Two caveats before repeating it. It is a FIXED TRADE, not a free win:
that gain cost −1.5 flores, −1.5 ted, −3.2 ui, and adding 29% long-form plus
sentence-splitting to counter that moved everything by under a point in both
directions, so the composition is not the lever — finetuning on ~120k after 4M
shifts the model toward those 120k whatever is in them. And judge it on ALL
slices; the one it was aimed at will always look good. See `ka_findings.md` §15.
CONTEXT (diagnosed on tl→en, see Pillar 2): the student lands ~5-6 chrF below the teacher on FLORES. The hypothesis was a KD-SOURCE-DOMAIN gap (student learns the teacher on crawl-domain source) fixable by clean eval-adjacent teacher labels.
1. **Domain-adaptive KD-finetune — TESTED, DOES NOT WORK.** Teacher-translated 163k clean Leipzig-wiki Tagalog and finetuned the KD ckpt on it → FLORES **59.88**, WORSE than the shipped human-curated finetune (60.57), with KD-agreement UP (72.83). Lesson: more teacher-labeled data (even clean/wiki) reinforces teacher-STYLE and does NOT close the human-ref gap; the FLORES-lifting signal is HUMAN references. Do not repeat this approach. Full analysis → Pillar 2 "FOLLOW-UP EXPERIMENT".
2. **Re-KD from scratch** — fold clean monolingual into the KD source POOL and retrain. UNTESTED and now expected MODEST (a pure clean-teacher finetune reinforced style rather than helping), so NOT worth ~$8 on spec.
**What actually gates a low-resource pair's FLORES** (revised): HUMAN parallel finetune SUPPLY (the real constraint — scarce for low-resource), TEACHER quality, and STUDENT CAPACITY (the ~6 student-vs-teacher gap looks like KD compression → a bigger student is the most promising untried lever). Leipzig Tagalog inventory for reference: only `tgl_wikipedia_{2016,2021}_100K` (~163k unique after dedup).
3. **Bicleaner-salvage finetune — PROVEN (sw→en +1.6 chrF++), but DIRECTION-DEPENDENT.** Expand the tiny curated finetune set by salvaging genuinely-aligned HUMAN pairs from the noisy mined pool (the ones we excluded from finetune for semantic-misalignment risk). Recipe (Swahili 2026-07-14, ~$3 all-in):
   - Install: `pip install bicleaner-ai "tensorflow[and-cuda]==2.20.0"` (bicleaner-ai is TENSORFLOW; needs a GPU box — CPU is ~130h for 6M pairs, GPU 4090 ~730 pairs/s ~2.25h). Model = **`bitextor/bicleaner-ai-full-en-xx`** (ONE multilingual XLM-R-large; works for any XLM-R language incl. sw — no per-pair model exists/needed).
   - Score the cleaned mined pool (2-col `src\ttgt`): `bicleaner-ai-classify --scol 1 --tcol 2 -s <xx> -t en --score_only --disable_hardrules --mixed_precision pool.tsv pool.scored bitextor/bicleaner-ai-full-en-xx`. `--disable_hardrules` because our pool is already heuristically cleaned; without it, needs the `bicleaner-ai[hardrules]` extra. (sw pool: mean 0.285, 64% junk <0.3.)
   - Keep **≥0.8** (sw: 908k of 6M), `align.sh` them, cat with the curated set, `finetune_student.sh` the KD ckpt on the merged set.
   - **ONLY boost the WEAK/large-gap direction, and judge by chrF NOT ce**: crawl-domain TARGET data lowers token-ce while it can HURT clean-domain chrF — sw→en (gap −7.7, clean English target) +1.6; en→sw (gap −1.6, crawl-Swahili target) −0.4 despite ce dropping 1.93→1.69. See RUN LOG "Swahili bicleaner boost".
FOR NEW LANGS (Swahili 2026-07-13): no cheap KD-source-domain fix exists — leave the KD pipeline as-is. FLORES levers in priority order (there is NO arch cap — see Pillar 2 gate-rule; base-memory→70 / tiny→75 chrF++ in our own catalog, all pair-bound): (1) **MORE HUMAN finetune data** = the real constraint — a low-resource pair's curated set is tiny (sw curated = only 9k pairs), so EXPAND it by running **bicleaner-ai over the mined corpora** (CCMatrix/CCAligned) to salvage genuinely-aligned human pairs → these are **finetune material** (both sides human; KD doesn't need them, the teacher regenerates targets), the cheapest real lever and the one that lifts FLORES *above* the teacher; (2) a **bigger student** (the ~6 student-vs-teacher gap is likely KD compression); (3) a **better teacher** (NLLB-1.3B/3.3B). Bicleaner deferred until after sw↔en ships.

# ▶ MOZILLA GAP ANALYSIS (2026-07-15) — why our students land below mozilla's (repo: ~/git/mozilla-translations)
CONTEXT: sw brittleness + tl −5.7 + the 1.3B re-KD failure prompted a line-by-line comparison with mozilla/translations (the Bergamot recipe we descend from). Their `student.base-memory.yml` is IDENTICAL to ours (384 / ssru dec-4 / bidir-gru enc-6 / ffn-1536) → **arch/capacity is NOT the differentiator; the KD corpus contents are.** Four structural deltas:

1. **extract-best (the biggest miss)** — their KD decode is beam 8 `--n-best`; per line, `pipeline/translate/extract_best.py` keeps THE ONE hypothesis with the best sentence-chrF/BLEU **vs the HUMAN reference**, discards the rest (task `distillation-parallel-src-extract-best`). Mechanics that matter: beam rank-1 = best under the TEACHER'S OWN distribution (its favorite errors included); reference-best = the most human-like thing the teacher can say. Targets stay 100% teacher-styled (fluent, consistent, compressible) — the reference is a JUDGE, never a target → human signal at FULL KD scale with ZERO distribution mixing (this resolves the "human data would drown in 5M" objection; drowning only applies to mixing human TARGETS in). Our KD source IS the bitext source side → ~100% of our KD lines already have a reference sitting in the cleaned bitext (mozilla only has refs on the parallel portion; their mono-src stays 1-best). COST: n-best output is FREE at a given beam (beam 4 already computes 4 hypotheses, we throw 3 away); beam 8 ≈ 2× decode, NOT 8×. CT2: `num_hypotheses=N`. **REFERENCE-QUALITY CAVEAT (2026-07-15, revises the Pillar-3 "KD source noise is irrelevant" doctrine)**: irrelevance held for 1-best (teacher regenerates the target); under extract-best the REFERENCE side matters — a semantically-misaligned reference makes "closest to reference" mean "closest to noise". Mitigations in order: (a) degradation is graceful — under a garbage ref all N teacher hypotheses score ~equally low chrF, selection goes ~random among teacher-fluent candidates ≈ 1-best quality, so a bad ref WASTES the opportunity rather than poisoning the pair; (b) **bicleaner-GATE it** (mozilla's answer = bicleaner the whole pool upfront): extract-best only where the pair's bicleaner score clears a threshold, 1-best elsewhere — sw pool scores need REGENERATING (~$1, died with the destroyed box); (c) targeted SOTA-model reference generation ONLY for flagged slices (~$1-3k scale) is the escalation for reference-starved pairs (uig), never the default — full-KD-scale generated references cost $10k+/pair = the wrong way.
2. **ce-filter** — after KD, `marian-scorer` + a BACKWARD model scores (teacher-output → original-source) with `--normalize` (length-normed logprob), sort, **drop worst 5%** (`pipeline/cefilter/`, remove=0.05). Kills teacher hallucinations / source copies / wrong-language output before the student sees them. Backward model = shallow `s2s` RNN (marian wmt2017-uedin example cfg, early-stopping 5) trained on the RAW HUMAN bitext → INDEPENDENT of any teacher. A teacher-descended reverse student is a CORRELATED judge — it misses teacher-shared errors but rarely flags good pairs → usable as a CONSERVATIVE first pass (lower bound on benefit); the RNN is the proper fixture, needs only bitext, trainable before any teacher exists (and doubles as the BT model).
3. **teacher trained ON the pair** — transformer-big, two-stage curriculum (pretrain original+back-translated 0.6/0.4 → FINETUNE on original human bitext until early-stop), subword-reg `sentencepiece-alphas 0.5`, OpusTrainer aug; ensembling supported but they run 1 now ("boost marginal"). This kills both halves of our diagnosed KD-domain/label gap: the teacher has SEEN the crawl domain (no NLLB-degrades-on-noisy-input effect) and is human-anchored BEFORE KD. NB: BT strengthens the TEACHER, never the student — our failed sw back-translation injected it at student-finetune, the wrong place. Cheap approximation for us: finetune NLLB on the pair's bicleaned bitext pre-KD.
4. **scale + eval** — mono-src KD up to 300M lines (HPLT/NLLB mono, monocleaner-filtered), bicleaner-ai upfront on everything incl. teacher data; eval = BLEU/chrF + **COMET22** + `flores_aug-*` robustness variants (typos/upper/noise/inline-noise). COMET22 is neural and catches wrong-content-word errors — the closest automatable proxy to our probe-set; "ce/chrF lied 4×" would plausibly not have happened under COMET.

**TWO TIERS OF HUMAN DATA (2026-07-15 — keep these apart, conflating them caused real confusion)**. **Tier A = curated/scarce** (sw: 9k curated; uig: the 5-10k SOTA-generated pairs): sized in the thousands, NEVER the KD reference (sizes are off ~400×) — its roles are (1) probe/calibration set ~1-2k, (2) the student finetune (which STAYS: it's also the QAT pass and buys +2-3 chrF; the critique was only that it must not be the SOLE human-signal carrier), (3) teacher anchor/SFT (the uig 2.5k en→ug tranche IS this role). **Tier B = mined bitext at KD scale, free**: our KD source IS the bitext source side (kd.sw.gz cut from train.ensw.sw.gz) → every KD line already carries its own reference in the same corpus — extract-best just stops throwing that column away; nobody GENERATES references. Tier B also supplies the backward-RNN training set (the bicleaner ≥0.8 slice). Judge appetite scales with KD size (millions) → only Tier B can feed it; finetune appetite is thousands → only Tier A fits. Nothing moves FROM the finetune TO the reference role.

**UNIFYING READ — human-signal placement**: mozilla has NO human-bitext student finetune AT ALL — their student "finetune" step is QAT-only (`quantize-bits: 8`, browsermt recipe) on the SAME distilled corpus. All human signal enters UPSTREAM (teacher-finetune stage + extract-best + ce-filter), at KD scale. Our 9k-curated finetune does the same job downstream with ~3 orders of magnitude less leverage — which is why it buys only +2-3 chrF and why every attempt to scale it (bicleaner 916k, BT 228k) was unstable. (Our finetune stays — QAT is folded into it — but it stops being the sole human-signal carrier.)

**RE-READS of past negatives**: tl −5.7 / sw→en −7.7 = student only ever sees unfiltered 1-best off-domain teacher output. 1.3B re-KD regression = "KD compression mismatch" PLUS unfiltered-hallucination poisoning (a richer teacher on noisy crawl emits richer GARBAGE and nothing removes it; "mbweha wa molten" is the signature). **Bigger-student lever DEMOTED** — mozilla ships the identical base-memory cfg and scores higher.

**SHORT-INPUT DEGENERACY** ("hallo → Hello in the hello"; mozilla #210/#215 — they FIXED it): root cause = cleaners strip short pairs → 1-word input is OOD → decoder free-runs. Their fix was DATA: keep short pairs in cleaning + add short-heavy datasets (LinguaTools-WikiTitles 7M title pairs, XLEnt, Tatoeba, tldr-pages — see `configs/short-sentences/`). WE ARE EXPOSED TWICE: fastText `min-lid 0.5` on BOTH sides kills single-word pairs (LID is unreliable on 1-2 words), and our allowlist deliberately excludes XLEnt as "entity junk" — for short-input robustness those pairs are the medicine. # ▲▲▲ LAYER 3 — per-pillar detail + gotchas

## 1. PIPELINE  (phase → script → where → ~time)
- **P0 gate** — validate_teacher.py (OPUS-MT) / nllb_gate.py (NLLB) → FLORES-200 devtest chrF++/spBLEU. bigserver CPU, cheap. Decide teacher before spending GPU.
- **P1 prep** — prep_data.py → cleaned en↔X bitext + joint 32k SPM. bigserver CPU, ~20-30min (parallelized).
- **P2 KD** — distill_data.py (CT2 int8 teacher forward-translate) → synthetic targets. vast GPU, ~5-6h/5M; SHARD across N boxes.
- **align** — align.sh (fast_align) inside marian container → 3-col guided-align TSV. bigserver, ~20min/10M.
- **P3 train** — train_student.sh (marian.cuda + OpusTrainer) → base-memory student. vast GPU, converges in a few h.
- **P3b finetune** — finetune_student.sh (quantize-aware, on curated clean set). vast GPU, ~1h.
- **P4 quant** — quantize_export.sh (browsermt 3-step int8) + shortlist.sh (SPM-subword). bigserver container, <20min.
- **bench** — benchmark_slimt.py (slimt on FLORES). laptop, <5min.
- **deploy** — package→bucket→gcs_models.json→regen_index→sync.sh. laptop, <30min.
Strategy: validate the WHOLE chain FREE on bigserver CPU (micro-train + quantize + confirm slimt loads/translates/emits alignments) BEFORE renting GPU.

## 2. TEACHERS
- **`gen_sft.py` gained `--backend codex` (OpenAI `codex exec`), `--effort` and
  `--max-cost`.** Measured en→ka against human references: `gpt-5.6-luna` at
  effort `low` beat `claude sonnet` by +2.50 chrF++ on FLORES, beat the
  LMT-60-8B NMT teacher by +2.3 to +5.5 on three of four slices, ran 7x faster,
  and spends a DIFFERENT quota than the Max plan. Reasoning effort is FLAT for
  translation — none/low/medium/high/xhigh spanned 0.7 chrF and 0.17 COMET while
  xhigh burned 4x the tokens — so use `low` and do not pay for thinking.
  `--max-cost` stops DISPATCHING at a budget, but can overshoot by up to
  workers x batch, since in-flight batches must finish.
- **Curated frontier data lifts a student ABOVE its teacher.** The tl doctrine
  that only HUMAN references do this is too narrow: a luna/sonnet-generated
  finetune set put the en→ka student 8.67 chrF++ over its teacher on camera-path
  sign strings, and reading the output confirms real corrections rather than
  style agreement. What does NOT work is more of the SAME teacher's output.
- Student arch = **base-memory** (dim-emb 384, dec-cell ssru dec-depth 4, enc gru bidir depth 6, ffn 1536, tied-embeddings-all). `tiny` = 256/dec-2 (id-en, ru-en).
- **base-memory vs tiny — UNRESOLVED (no rule that avoids two training rounds)**: shipped major packs use base-memory (bigger, better when the data supports it); a few pairs use tiny. Upstream's "Small fixes around fp16 training and batch fitting" fixes both (casts the multi-loss before accumulation; throws/CATCHES `ShapeSizeException` during fitting) and inherits 4b51dcbd, which makes guided alignment SPARSE. Measured on a 4090: old-pin fp32 **142k w/s** → new-pin fp32 **161k** (+13.6% from sparse alignment alone) → new-pin **fp16 ws12000 211k (1.50x)**. Do NOT drop guided-alignment to get fp16 (it was the only way on the old pin): it produces the alignment head, and when align_ensw degraded it the note was "chrF unaffected; **bold/format transfer** is what suffers". Validated end to end: npz → browsermt `marian-conv` → slimt loads AND translates, 31,561,697 B (shipped packs 31,561,635 B).
- **Train flags: `--fp16 --workspace 12000 --mini-batch 4000`.** fp16 halves activation memory and `mini-batch-fit` spends it automatically (552 → 2133 sen/update at the same workspace), so the 1.5x already INCLUDES the batch growth; ws12000 adds ~5%; ws≥15000 still trips the fit probe. `train_student.sh` takes an EXTRA arg for these and its default `--workspace` now yields when EXTRA sets one (passing it twice is ambiguous).
- **GPU is NOT dataloader-starved; it is launch-bound.** 300 samples @100ms on the fp32 baseline: mean 85.3%, **zero below 50%, no idle gaps** — many small kernels on a dim-384 model, not stalls. OpusTrainer used 13–16% of ONE core to feed 142k w/s (22.5% at 215k), so the producer was never the bottleneck. This is why materialising the augmented corpus was evaluated and REJECTED (see train_student.sh), and why 2-GPU starves on marian's OWN reader.
- **2-GPU: 1.96x throughput but only ~1.3x to equal quality — and `--mini-batch-words-ref` is MANDATORY if you use it (2026-07-21).** `--devices "0 1" --sync-sgd` on the real corpus: 415,904 w/s vs 212,157 (1.96x) at 89%/58% util, ~1.93x the price. But sync-sgd DOUBLES the effective batch (2945 → 5719 sen/update), so at equal data the run has taken HALF the updates AND sits at HALF the lr — `lr-warmup` is indexed in UPDATES — i.e. ~4x less parameter movement per sentence. Uncorrected, CE at ~28.5M sentences was **4.095 vs the 1-GPU's 2.382 at 29.5M**. With `--mini-batch-words-ref 53752` (the 1-GPU words/update; marian scales lr by mbSize/ref inside `OptimizerBase::update`, so the SCHEDULER's logged `L.r.` never shows it) that recovers to **3.126** — 57% of the gap. Per WALL CLOCK the 2-GPU run is nonetheless ahead at every point (3.126@26min vs 1-GPU 4.030@23min; 1.995@51min vs 2.382@44min), because data is unlimited here and only hours are scarce. Realistic time-to-equal-CE speedup ~**1.25–1.35x**, not 1.96x. An earlier 1.54x measurement was WRONG — it used a 200k-line head slice that gives 65% util where the real corpus gives 91%.
- **early-stopping is denominated in validations but PAID IN WALL TIME.** A validation costs ~3s (997 lines) against ~292s of training per 1000 updates, yet at the old `valid-freq: 5000` four of them was ~100 min — ~35% of a 4–5h run. Now `valid-freq: 1000` + `early-stopping: 4` + **`early-stopping-epsilon: 0.01`** = ~20 min of patience at ~1% overhead. Epsilon is what stops the "never terminates" case: with the default 0, ANY improvement resets patience, so a run producing −0.002 per validation runs forever (this is what "manually stopped at plateau" in the tl v2 log below actually was).

- **pipe: the step key does NOT cover argv or configs (2026-07-21). This is a live correctness trap.** `_key` hashes {step, image, script digest, inputs, `args`} — the argv returned by the step function is absent (it cannot be included: `ctx.out_dir` depends on the key). So a FLAGS-ONLY change is invisible: `tlkd` (1 GPU) and `tl2gpu` (2 GPU, different `--devices` and `--mini-batch-words-ref`) hashed to the SAME key, shared an output directory, and had the earlier step been `done` rather than `running` the corrected config would have been **silently memoized away**. Pass `args={...}` for anything that changes the command — `flows/pack.py` already does this with "infix". **STILL UNFIXED and worse: `configs/*.yml` are read at runtime and are NOT hashed either**, so changing `learn-rate`, `early-stopping`, or the model architecture in `student.base-memory.yml` invalidates NOTHING — a rerun can be skipped, or `pipe adopt` can hand you outputs trained under different hyperparameters.
- **pipe: `pipe put` during a running step was SILENTLY LOST (fixed 2026-07-21).** `Ledger.__init__` read the file once and `save()` wrote the whole in-memory copy back, so a runner holding its copy across an hours-long step clobbered any concurrent `put` — which had reported success and returned a digest. Cost vocab/valid/flores_src during a 19-min align; the train flow then died on "no artifact vocab in this run". `save()` now takes an flock, re-reads, and applies only ITS OWN changed keys (`_dirty_*`), adopting the merged state — so a long runner also SEES artifacts registered while it worked. Regression test: `tests/test_ledger_race.py`.
- **pipe: a ghost step made a run un-abortable (fixed 2026-07-21, needs a `piped` restart to take effect).** An aborted step is left RUNNING in the ledger (`action: "left"`); salvage then dialled its long-destroyed box on EVERY later abort, and paramiko's `NoValidConnectionsError` — which subclasses `OSError` DIRECTLY, not `SSHException`, not `ConnectionError` — escaped both the ssh retry tuple and salvage's `except RuntimeError`, failing the abort before it reached the LIVE step. That is the exact moment abort matters, because a box is burning money. Now: `_retry` catches `OSError`; salvage marks a lease-less RUNNING step `orphaned` instead of dialling it; and per-step failures no longer stop the loop from destroying the OTHER boxes. Note `piped` holds its modules in memory — code fixes need a daemon restart, and restarting it while a run is training risks its runner (a child process) being read as dead.
- **vast: use `--direct`, and compress transfers (2026-07-21).** `create` passed only `--ssh`, i.e. vast's PROXY mode, so every byte relayed through their US-west gateway — an EU hub → EU box crossed the Atlantic twice at **1.15 MB/s** (a 1.96GB upload took ~28 min with the rented GPU idle at 17W), and that proxy is what drops connections mid-transfer. `--direct` is a one-flag fix and every offer already has the ports (52/52 measured; `direct_port_count` filters NOTHING, and the UI's `static_ip` — 13/52 — is a different property). `Instance` now splits `proxy_*`/`public_*` with an `endpoint` property preferring direct, and `pipe ps` reports the route. rsync also gained `-z` (3.0x zstd on train.tsv; rsync 3.2+ negotiates the compressor, so no `--compress-choice`). Caveat: the endpoint is resolved at rent time and a box whose port mapping has not appeared yet records the PROXY.
